# 智能模式 vs 定时模式对照方案

任务书要求定时模式独立可用。两种模式共享采集与写盘管线，仅策略源不同。

## 对照维度

| 维度 | 定时模式 | 智能模式 |
|---|---|---|
| 触发条件 | 固定间隔（默认 30s，可调） | 画面内容变化（两级检测）+ 心跳保底 |
| 依赖 | 无（不需要检测参数成立） | 320×180 灰度 + 1fps + 冻结阈值 |
| 静态画面 | 每间隔一张（大量冗余） | 仅心跳保底一张（默认 10s） |
| 快速变化 | 按间隔，可能漏掉中间状态 | 持续性确认 + 缓冲回存 + 动态采样 |
| 单帧闪动 | 不受影响 | blip rescue 语义决定保留/丢弃 |
| CPU | 极低（几乎只做采集+编码） | 低（检测 <0.01% 预算，见 performance.md） |
| 故障面 | 小（检测失效不影响出图） | 检测参数/分辨率被改动会退化 → 心跳兜底 |

## 验证方案（智能 vs 定时对照实验）

在同一次真实课程上并行跑两个会话（不同输出子目录），比较：

1. **覆盖率**：定时（30s）保存集合 S_t，智能保存集合 S_s。
   统计 S_t 中每张图的"上一次相似画面"在 S_s 中的对应间隔——
   智能模式应在画面不变时把间隔拉长到心跳级别，在变化时把延迟压到 persist-1 秒内。
2. **冗余率**：相邻两张保存的 XOR 位数 < prefilter 的比例。定时模式在静态段冗余率应接近 100%。
3. **张数**：同一课程 S_s vs S_t 的数量比。研究在真实数据上的预期是智能模式显著更少
   （参考回放：20.mov 5862 帧智能只保存 248 张 ≈ 4.2%；若定时 30s 会保存 ~195 张且分布均匀）。
4. **漏检核查**：人工抽查 S_t 中存在而 S_s 中缺失且画面确实变化的时刻（重点：细笔画、小字变化，
   见 known-limitations 的预筛限制）。
