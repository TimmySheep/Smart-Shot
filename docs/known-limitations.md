# 已知限制与风险

按"未验证的风险必须明确记录"原则整理。区分：**已验证的限制**（有测试或分析固化）
与**未验证的风险**（尚未在真实环境确认）。

## 已验证的限制

### 1. 预筛阈值下的小变化漏检（冻结配置固有折中）

第一级 XOR 预筛（8000 位）挡掉的变化不会进入区域分析。
合成场景实测：约 480 像素的细笔画批注（~1500–3800 位）**确实漏检**
（`testThinAnnotationMissedWithFrozenPrefilter` 固化此行为）。

- 这是研究在误报/漏检间选定的折中，不是移植缺陷。
- 真实场景中低分辨率下笔画覆盖更多像素，比合成场景更易过预筛，但不能保证。
- 缓解：心跳保底兜底（默认 10s）；可调低 prefilterBits 换取更高误报。

### 2. 分析分辨率与帧率是冻结阈值的成立前提

阈值（8000 位/20 像素/3000 像素）只在 **320×180 灰度、1fps** 下有效。
研究实测 2/5fps 未重新校准会恶化精度。UI 中更高检测帧率已标注实验性。
改分辨率/帧率必须重新调参，否则检测行为不可预测。

### 3. blip rescue 关闭时 1 秒瞬变画面漏检

persist=2 凑不满时无抢救机制即丢弃（`testBlipMissedWhenRescueDisabled` 固化）。
默认开启 rescue，此为配置风险而非默认行为。

### 4. vImage 与 ffmpeg 转换不逐位一致

真实采集用 vImage（双线性）缩放到 320×180；研究管线用 ffmpeg scale。
两者亮度语义接近（均为 BT.601 加权），但**不保证逐位相同**，
因此真实画面下的触发点与离线回放存在小概率偏移。等价性测试只覆盖
「已是 320×180 灰度」的输入。

### 5. 心跳语义：`heartbeatSeconds <= 0` 即关闭

与 Python 参考的 falsy 语义对齐。App 默认 10s；设为 0 表示完全无保底
（不推荐：检测失效时会产生盲区）。

### 6. 冷却从首帧保存就开始计时

cooldownSeconds > 0 时，会话开始后前 cooldown 秒内的变化会被抑制
（首帧保存也是保存）。默认 cooldown=0（研究验证配置），不影响默认行为。

## 未验证的风险（需真实运行确认）

1. **真实采集链路**：SCStream → vImage → 策略 → 写盘 的端到端行为、
   目标窗口关闭/最小化时的表现、多显示器/缩放分辨率下的坐标处理——
   代码已写但未在授权后实测。
2. **30 分钟稳定性**：连续运行的内存、句柄、CPU 未实测。
3. **TCC 权限稳定性**：Apple Development 签名 + hardened runtime 理论上
   权限可跨重建保持，但未实测「授权后重新构建再运行」。
4. **动态采样模式**：连续动态画面的进入/采样/退出是 App 层新增
   （研究未覆盖），仅有合成场景测试，无真实影片验证。
5. **Xcode 27 签名链**：Automatic 签名已构建成功，但 Xcode 27 beta 期间
   签名行为可能变化（release notes 提及 manual signing workaround）。
